# Сповіщення власниці

Справжній Web Push працює через service worker, навіть коли вкладка закрита. Реєстрація покупців, електронні листи, платний сервіс та обліковий запис розробника Apple не потрібні. Дозвіл на сповіщення надає власниця на кожному пристрої.

## Налаштування сервера

1. Встановіть залежності: `python3 -m venv .venv` та `.venv/bin/python -m pip install -r requirements.txt`.
2. У `.env` задайте `BAKERY_PUSH_SUBJECT=https://ваш-справжній-домен` або `mailto:ваша-справжня-пошта`. Це контакт для push-служби, а не відправник листів. Для локального тесту теж можна використати справжню контактну пошту. Значення не потрібно показувати покупцям.
3. Для телефона опублікуйте сайт через HTTPS із постійно запущеним Python-сервером за reverse proxy. `127.0.0.1:8013` доступний лише цьому комп’ютеру. Встановіть `BAKERY_SECURE_COOKIE=1` на HTTPS. Reverse proxy має зберігати Host. Потрібен вихідний HTTPS до push-служб Apple, Google, Mozilla та Microsoft. Нинішній локальний запуск не є хостингом.
4. Перезапустіть `./start.sh --port 8013`. Ключ VAPID генерується автоматично в `data/push-private.pem` (права 600). Збережіть його разом із резервною копією бази. Не публікуйте `data`, `.env` або приватний ключ; frontend отримує лише відкритий ключ. Видалення/зміна ключа вимагає вимкнення та повторного ввімкнення підписки на кожному пристрої.
5. У кабінеті відкрийте «Сповіщення про замовлення» → налаштування та натисніть **«Увімкнути сповіщення»**, дозвольте їх браузеру, потім **«Надіслати пробне»**.

На iPhone/iPad потрібна iOS 16.4+ та встановлення через Safari → Поділитися → На початковий екран. Відкрийте встановлений застосунок перед ввімкненням. На Android використовуйте підтримуваний браузер (наприклад Chrome); встановлення доступне через меню. Вбудований браузер Viber може не підтримувати push: для кабінету відкрийте системний браузер. На комп’ютері дозвольте браузеру працювати у фоні та перевірте системні налаштування сповіщень.

## Перевірка

Натисніть пробне сповіщення. Потім закрийте вкладку та оформіть бронювання з іншого браузера. Має прийти «Нове замовлення №…». Натиснення відкриває конкретне замовлення у кабінеті; без чинного входу спершу з’явиться форма пароля. Повторіть для особливого торта. У кабінеті також можна вимкнути сповіщення саме на цьому пристрої. Вихід із кабінету не відписує пристрій.

Замовлення та завдання надсилання зберігаються однією транзакцією SQLite. Повторне надсилання тієї самої форми не створює додаткового повідомлення. Фоновий обробник відновлює чергу після перезапуску, робить до 5 спроб, припиняє повтори через 24 години, вимикає підписки з відповіддю 404/410. Доставка може затримуватися або блокуватися ОС. «Прийняте службою доставки» не гарантує показ на телефоні. Якщо щось не прийшло, відкрийте кабінет і перевірте стан та пробне повідомлення. Імена, телефони, суми, алергії й особисті посилання покупців не передаються у сповіщеннях. Service worker не кешує приватні сторінки.

Зараз автоматичні тести перевіряють чергу й обробку відповідей із підставною push-службою. Реальну доставку потрібно перевірити на телефоні після налаштування адреси та дозволу.

Офіційні вимоги Apple: https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers
